# 기존 패킷으로 결산 후 로비 복귀

## 클라이언트 동작

1. 타이머 0초에 신규 접수와 플레이어 조작을 막는다. 이미 접수한 로컬 제출 큐는 계속 전송하고, 집계 중에는 HUD `00:00`과 예정 콩 갱신을 유지한다. 서버의 집계 완료 신호인 `S_StageStop`을 받으면 게임 종료/결산 팝업을 표시한다. 빈 접시 배출 완료를 기다리지 않으며, 진행 중인 배출도 결산 때문에 취소하지 않는다.
2. 복귀 요청/준비 완료용 새 패킷은 보내지 않는다. 결산 화면의 복귀 버튼도 숨기고 로비 복귀 알림을 기다린다.
3. `S_OpenDoor`의 `DoorId.Lobby`를 받으면 서버의 이전 판 정리가 끝난 신호로 취급한다.
4. 씬의 `LobbyReturnSpawnPoints`에서 참가자별 위치·회전을 읽어 이전 판 로컬 상태 정리 → 로비 이동 → 페이드 아웃 → 조작 재활성화를 실행한다.
5. 다음 판은 기존 스테이지 선택·시작 패킷을 사용한다. 결산과 복귀 중에는 Tab 테스트 시작을 막는다.

팀 지갑과 결산 기록은 유지하며 복귀로 재화를 다시 더하지 않는다. 접수 시각 기준과 제출 패킷은 이 작업에서 변경하지 않았다.

## 씬 설정

- 씬에 `LobbyReturnSpawnPoints` 컴포넌트 하나를 추가한다.
- Spawn Points 배열 0번은 로비 UI의 참가자 1, 1번은 참가자 2의 스폰 Transform을 지정한다. 두 클라이언트는 같은 씬 배치를 사용한다. 내 플레이어를 무조건 0번에 두는 방식은 사용하지 않는다.
- Reset Map Registration은 현재 서버처럼 종료 시 모든 엔티티 ID를 지우면 켠다. 고정 도구 ID를 유지하는 서버 정책으로 바뀌면 끈다.
- 설정이나 참가자 스폰 정보가 없으면 로비 문 패킷을 버리지 않고 설정을 기다린다. 임의 위치로 이동하지 않는다.
- 초기 방 입장 때의 로비 문 알림이나 중복 복귀 알림은 결산 후 복귀로 반복 처리하지 않는다.
- 로비 알림 시 주방 문은 다시 활성화하고 닫는다. Tab 테스트에서 비활성화했던 문도 복구한다.

## 서버 담당자 요청

- 0초 이전 접수한 요리의 판정·보상 집계를 모두 끝낸 후 기존 `S_StageStop`으로 결산 결과를 방송한다. 기존 제출 패킷에는 접수 시각이 없으므로 서버에 늦게 도착한 클라 큐의 시각 보장은 별도 합의가 필요하다.
- 서버가 정한 결산 표시 시간 이후, 이전 판 주문·재료·조리·제출 대기·타이머와 플레이어/문 상태를 초기화한다. 팀 지갑과 참가자 정보는 유지한다.
- 정리가 끝나면 기존 `S_OpenDoor { DoorId = Lobby }`를 방 전체에 방송한다. 이 패킷 이후에 이전 판 데이터를 다시 만들거나 이전 주방 위치를 덮어쓰지 않게 한다.
- 중복 시작·종료를 방지하고 다음 2인 진입 때 기존 시작 경로가 다시 작동하게 한다.
- 준비 완료 확인 패킷은 사용하지 않는다. 서버는 복귀 연출 시간을 고려해 다음 시작을 허용한다.

로비 스폰 좌표는 새 패킷으로 전달하지 않는다. 서버에서 위치 정보가 필요하면 클라이언트 씬과 같은 스폰 배치를 사용한다.

## 로컬 정리 범위와 확장

주문/피드백 UI, 재료 생성 대기열, 네트워크 오브젝트 풀 반환, 제출·반환 대기, 솥·오븐·팬·화구·작업대 상태, 선택적인 맵 도구 ID 정리, 플레이어 잡기·행동·로켓·체력·입력·속도·원격 보간 초기화를 연결했다.

바닥 오염·이벤트 전용 구현은 아직 찾지 못했다. 해당 컴포넌트가 `IClientStageResettable.ResetClientStage()`를 구현하거나 `ClientStageResetHook`의 Reset Stage 이벤트에 초기화 함수를 연결하면 같은 시점에 실행된다. 초기화 콜백은 서버 요청을 보내지 않는다.

칼·팬·접시의 실제 수량과 초기 배치는 별도 작업에서 관리하며 이 흐름이 새로 스폰하지 않는다.

## 검증 범위

전체 런타임 컴파일, 로컬 복귀 상태 전이와 중복 처리, 참가자 순서별 스폰 매핑, 기존 패킷 직렬화를 검사한다. 정상 2인 네트워크 경로의 두 번 연속 플레이는 서버의 로비 문 방송 처리 후 확인해야 한다.
